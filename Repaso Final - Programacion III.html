Cómo usar esta guía

Cada problema sigue el mismo formato: descripción (qué resuelve), características, tipo de entrada y complejidad (con \(a,b,k\) y tipo de recurrencia), sin pseudocódigo. Hay ejercicios resueltos con botón para revelar la solución (probá resolver antes de mirar), una autoevaluación con 30 flashcards y un checklist que se guarda en tu navegador.

Ojo para el examen: el simulacro de cátedra sí pide escribir pseudocódigo en el Ejercicio 1 (construir el árbol del juego) y en el Ejercicio 4 (algoritmo de PD). Este material es descriptivo por tu preferencia de estudio, pero conviene que practiques escribir el algoritmo para esos dos.
Estrategia de las 2 horas: arrancá por el ejercicio que más domines para asegurar el 50%. Antes de cada respuesta, identificá qué técnica es (juego→MinMax, optimización con cota→B&B, recorrido→DFS/BFS, tabla→PD, recurrencia→complejidad). Ese diagnóstico correcto es medio ejercicio.

UVA 1 Complejidad Temporal

Idea central: es una forma de saber qué tan rápido es un algoritmo sin usar cronómetro. En vez de medir segundos (que dependen de tu compu y del lenguaje), contás cuántas operaciones hace según el tamaño de la entrada \(n\). Siempre miramos el peor caso: si aguanta ahí, aguanta en todos los demás.

Jerarquía de complejidades (de mejor a peor)

NotaciónNombreEjemplo típico
\(O(1)\)ConstanteAcceso a un array, una asignación
\(O(\log n)\)LogarítmicaBúsqueda binaria
\(O(n)\)LinealBúsqueda lineal, un ciclo simple
\(O(n\log n)\)Linearítmica (\(n\log n\))MergeSort, Heapsort, QuickSort promedio
\(O(n^2)\)CuadráticaCiclos anidados, burbujeo, selección
\(O(n^3)\)CúbicaFloyd-Warshall, multiplicación de matrices clásica
\(O(2^n)\)ExponencialFibonacci sin memoización, suma de subconjuntos
\(O(n!)\)FactorialGenerar todas las permutaciones, TSP por fuerza bruta
Orden de crecimiento: \(O(1) \prec O(\log n) \prec O(n) \prec O(n\log n) \prec O(n^2) \prec O(n^3) \prec O(2^n) \prec O(n!)\). Para \(n\) grande, un algoritmo \(O(n\log n)\) le gana siempre a uno \(O(n^2)\), aunque para \(n\) chico el de constante mayor pueda parecer más rápido.

Notaciones asintóticas

  • \(O\) — cota superior (peor caso).
  • \(\Omega\) — cota inferior (mejor caso).
  • \(\Theta\) — cota ajustada (\(O\) y \(\Omega\) coinciden).

Reglas prácticas de conteo

  • Secuencia de operaciones → se suman las complejidades (queda la mayor).
  • Condicional → costo de la condición + máximo de las dos ramas.
  • Ciclo → \(N\) × costo del cuerpo.
  • Llamada a método → \(1\) + complejidad del método.
Regla rápida: cada ciclo anidado agrega un grado al polinomio → 1 ciclo \(O(n)\), 2 ciclos \(O(n^2)\), 3 ciclos \(O(n^3)\). Y al sumar, gana siempre el término más grande (\(O(n)+O(n^2)=O(n^2)\)); las constantes se ignoran (\(O(5n)=O(n)\)).

Recurrencias: sustracción vs. división

Definición formal (como en la diapositiva de cátedra): el caso base \(c\) es constante para entradas chicas, y según la relación entre \(a\) y \(b^k\) (o \(a\) y 1) se aplica una de tres fórmulas. Con \(p(n),\,f(n)\in O(n^k)\).

MÉTODO DE SUSTRACCIÓN — \(T(n-b)\)

\[ T(n)=\begin{cases} c & \text{si } 0\le n\lt b\\ a\,T(n-b)+p(n) & \text{si } n\ge b\end{cases} \] \[ T(n)\in\begin{cases}\Theta(n^{k}) & \text{si } a\lt 1\\ \Theta(n^{k+1}) & \text{si } a=1\\ \Theta\!\big(a^{\,n\,\mathrm{div}\,b}\big) & \text{si } a\gt 1\end{cases} \]

MÉTODO DE DIVISIÓN — \(T(n/b)\)

\[ T(n)=\begin{cases} c & \text{si } 0\le n\lt b\\ a\,T(n/b)+f(n) & \text{si } n\ge b\end{cases} \] \[ T(n)\in\begin{cases}\Theta(n^{k}) & \text{si } a\lt b^{k}\\ \Theta(n^{k}\log n) & \text{si } a=b^{k}\\ \Theta\!\big(n^{\log_b a}\big) & \text{si } a\gt b^{k}\end{cases} \]

La misma información en tabla rápida:

TipoFormaFórmula
Sustracción\(T(n)=a\,T(n-b)+p(n)\), con \(p(n)\in O(n^k)\)Si \(a=1 \Rightarrow \Theta(n^{k+1})\). Si \(a\gt 1 \Rightarrow \Theta(a^{\,n/b})\) (exponencial).

Cómo identificar los parámetros \(a\), \(b\) y \(k\)

Mirá una sola llamada recursiva del algoritmo y respondé tres preguntas:

Parám.PreguntaDónde mirar
\(a\)¿Cuántas llamadas recursivas se hacen?El número que multiplica a \(T\). En \(2\,T(\dots)\) → \(a=2\); si hay una sola llamada → \(a=1\).
\(b\)¿Cuánto se achica el problema en cada llamada?Si resta \(T(n-b)\) → es el número que se resta (sustracción). Si divide \(T(n/b)\) → es el divisor (división).
\(k\)¿Cuál es el costo del trabajo fuera de las llamadas?Ese trabajo es \(O(n^k)\): constante → \(k=0\); lineal (un ciclo) → \(k=1\); cuadrático (ciclos anidados) → \(k=2\).

El tipo lo define \(b\): si el tamaño baja restando (\(n-b\)) es sustracción; si baja dividiendo (\(n/b\)) es división.

Ejemplo de identificación
Identificá \(a,b,k\) y resolvé: \(T(n)=3\,T(n/4)+n^2\) y \(T(n)=2\,T(n-1)+O(1)\).

\(T(n)=3\,T(n/4)+n^2\): hay 3 llamadas → \(a=3\); el problema se divide por 4 → división, \(b=4\); el trabajo extra \(n^2\) es cuadrático → \(k=2\). Comparo \(a\) con \(b^k=4^2=16\): como \(a=3\lt 16 \Rightarrow \Theta(n^k)=\Theta(n^2)\).

\(T(n)=2\,T(n-1)+O(1)\): hay 2 llamadas → \(a=2\); el problema se reduce restando 1 → sustracción, \(b=1\); trabajo extra constante → \(k=0\). Con sustracción y \(a=2\gt 1 \Rightarrow \Theta(a^{\,n/b})=\Theta(2^{\,n/1})=\Theta(2^n)\).

Ejercicio resuelto 1.1
Clasificá y resolvé: \(T(n)=T(n/2)+O(1)\), \(\;T(n)=2T(n/2)+O(n)\), \(\;T(n)=2T(n-1)+O(1)\).

\(T(n)=T(n/2)+O(1)\) → división, \(a=1,\,b=2,\,k=0\). Como \(a=1=b^0 \Rightarrow \Theta(\log n)\). (Búsqueda binaria.)

\(T(n)=2T(n/2)+O(n)\) → división, \(a=2,\,b=2,\,k=1\). \(a=b^1 \Rightarrow \Theta(n\log n)\). (MergeSort.)

\(T(n)=2T(n-1)+O(1)\) → sustracción, \(a=2\gt 1 \Rightarrow \Theta(2^n)\). (Fibonacci recursivo puro.)

Ejercicio resuelto 1.2 (estilo Parcial 8-Nov)
metodo(conjunto[1..n], int n){
  bool cond = calcularUnDato(conjunto)   // O(n) lineal
  si (cond) { TrabajarCon(conjunto) }     // O(n^2) cuadratico
  sino { metodo(conjunto, n/2) }
}
Calculá la complejidad temporal.

Cada llamada cuesta \(\text{calcularUnDato}=O(n)\) más el máximo de las dos ramas. La rama recursiva es \(\text{metodo}(n/2)\).

Recurrencia (peor caso, siempre entra por el sino): \(T(n)=T(n/2)+O(n)\). Es división: \(a=1,\,b=2,\,k=1\). Como \(a=1\lt b^k=2 \Rightarrow \Theta(n^k)=\Theta(n)\).

El término dominante es el trabajo lineal de cada nivel, no la rama cuadrática (que solo ocurre en el caso base cuando cond es verdadero, una sola vez). Resultado: \(\boldsymbol{\Theta(n)}\).

UVA 2 Divide y Conquista

Tres pasos: Dividir (partir en subproblemas del mismo tipo), Conquistar (resolver recursivamente), Combinar (unir soluciones). Requisito clave: subproblemas independientes y de tamaño parejo (desbalancearlos degrada la complejidad).

Intuición: es como repartir una pila enorme de exámenes en dos mitades, que cada mitad la corrija otra persona (recursión), y al final juntar las notas. Funciona bien porque las mitades no dependen entre sí.

MergeSort vs QuickSort: MergeSort garantiza \(n\log n\) siempre pero paga memoria auxiliar. QuickSort es in-place pero su peor caso (array ordenado + pivote en el extremo) es \(\Theta(n^2)\); se mitiga con pivote mediana-de-3 o al azar.

Problemas clásicos desarrollados

Clásico 2.1 — Búsqueda binaria
¿Cómo funciona y por qué es \(\Theta(\log n)\)?

Qué resuelve: buscar un elemento en un arreglo ordenado. Características: se compara \(x\) con el elemento del medio; si es igual, listo; si \(x\) es menor, se sigue en la mitad izquierda; si es mayor, en la derecha. Cada paso descarta la mitad del arreglo. Entrada: un arreglo ordenado y el valor a buscar.

Complejidad: recurrencia de división \(T(n)=T(n/2)+O(1)\) con \(a=1,\,b=2,\,k=0\); como \(a=b^0=1 \Rightarrow \Theta(\log n)\).

Clásico 2.2 — MergeSort
Idea, por qué \(\Theta(n\log n)\) siempre, y su costo en memoria.

Dividir: partir el arreglo en dos mitades. Conquistar: ordenar cada mitad recursivamente. Combinar: merge de dos mitades ya ordenadas en \(O(n)\).

Recurrencia \(T(n)=2T(n/2)+O(n)\) → \(a=2,\,b=2,\,k=1,\ a=b^1 \Rightarrow \Theta(n\log n)\), sin importar el orden inicial (por eso es estable y predecible). Paga \(O(n)\) de memoria auxiliar para el merge — su desventaja frente a QuickSort in-place.

UVA 3 Greedy (Voraz)

Idea: en cada paso agarrás lo que parece mejor ahora y no volvés atrás nunca (por eso es localmente óptima). Es rápido, pero no siempre da el mejor resultado global: para cada problema hay que demostrar que la estrategia realmente funciona.

Por qué "voraz": es como alguien en un bufé que siempre agarra ahora el plato más grande, sin fijarse si más adelante hay algo mejor. Rápido y simple, pero esa avidez no siempre lleva al mejor resultado final (por eso hay que probar que funciona en cada problema).

Los 5 componentes de todo Greedy

  1. Candidatos: universo de decisiones posibles.
  2. Función de selección: criterio del "mejor" candidato en cada paso.
  3. Función de factibilidad: ¿el candidato mantiene la solución válida?
  4. Función solución: ¿la construcción está completa?
  5. Función objetivo: lo que se maximiza/minimiza.

Clásico 3.1 — Codificación de Huffman
Frecuencias \(A{:}5,\ B{:}2,\ C{:}1,\ D{:}1\). Construí el árbol y dá los códigos.

Criterio greedy: combinar siempre los dos nodos de menor frecuencia (cola de prioridad mínima) hasta tener un solo árbol.

Paso 1: C(1)+D(1) → nodo CD(2)
Paso 2: B(2)+CD(2) → nodo BCD(4)
Paso 3: A(5)+BCD(4) → raíz(9)

Códigos (0 = izq, 1 = der): A=0, B=10, C=110, D=111. Los más frecuentes quedan más cortos.

Longitud total \(=5\cdot1+2\cdot2+1\cdot3+1\cdot3=15\) bits. Complejidad \(\Theta(n\log n)\) por la cola de prioridad. Siempre óptimo.

Clásico 3.2 — Mochila fraccionaria
Capacidad \(W=20\). Objetos (valor, peso): \(A(60,10),\ B(100,20),\ C(120,30)\). Maximizar valor.

Ordenar por relación \(v/p\): \(A=6,\ B=5,\ C=4\). Cargar en ese orden, fraccionando el último si no entra completo.

Tomo A completo: peso 10, valor 60, resta 10
Tomo fracción de B: 10/20 → valor 100·(10/20)=50, resta 0
C no entra

UVA 4 Greedy sobre Grafos

Dijkstra — caminos mínimos desde un origen

Grafo dirigido con pesos positivos y un origen: hallar el costo mínimo a todos los nodos. Criterio greedy: elegir el nodo pendiente de menor costo acumulado; al marcarlo, su distancia queda definitiva.

Intuición: es como una mancha de tinta que se expande desde el origen tomando siempre lo más barato primero: en cada paso "confirma" el nodo pendiente más cercano y ya no lo vuelve a tocar. Por eso un peso negativo lo rompe: podría abaratar un nodo que ya dio por cerrado.
No funciona con pesos negativos (para eso está Bellman-Ford, fuera del programa). Complejidad \(O(n^2)\) con matriz de adyacencia; \(O((V+E)\log V)\) con heap + lista de adyacencia.
¿Y los caminos mínimos entre TODOS los pares? Dijkstra los da desde un origen (greedy). Para el mínimo entre todos los pares de nodos está Floyd-Warshall — pero es Programación Dinámica (\(\Theta(n^3)\)), así que lo tenés en UVA 5.

Ejercicio resuelto 4.1 (estilo Parcial 8-Nov)
"Conectar todas las ciudades A,B,C,D,E con el menor costo total, sin formar ciclos." ¿Qué algoritmo usás y cuál es su complejidad?

Es un Árbol de Recubrimiento Mínimo (MST): "conectar todo, mínimo costo, sin ciclos" es la definición literal. Sirven Kruskal (\(\Theta(a\log a)\), mejor en grafos dispersos) o Prim (\(O(n^2)\), mejor en densos).

Método a mano con Kruskal: ordenar aristas por costo ascendente y agregarlas una por una, salteando la que forme ciclo, hasta tener \(n-1\) aristas (con 5 ciudades → 4 aristas).

Clásico 4.2 — Dijkstra (ejemplo)
Grafo dirigido, pesos positivos. Aristas: \(A\!\to\!B(1),\ A\!\to\!C(4),\ B\!\to\!C(2),\ B\!\to\!D(5),\ C\!\to\!D(1)\). Caminos mínimos desde \(A\).
Inicio: dist(A)=0, resto=∞
Elijo A(0): relajo B=1, C=4
Elijo B(1): C=min(4, 1+2)=3, D=1+5=6
Elijo C(3): D=min(6, 3+1)=4
Elijo D(4): fin

Distancias mínimas desde \(A\): \(A{=}0,\ B{=}1,\ C{=}3,\ D{=}4\). En cada paso se fija definitivamente el nodo pendiente de menor costo acumulado. Complejidad \(O(n^2)\) con matriz de adyacencia.

UVA 5 Programación Dinámica

Dos condiciones necesarias:

  1. Subestructura óptima: la mejor solución del problema grande se arma juntando las mejores soluciones de sus pedacitos. Si armar bien las partes no te da bien el todo, PD no sirve.
  2. Superposición de subproblemas: los mismos pedacitos aparecen una y otra vez → en vez de recalcularlos, los anotás en una tabla y los reusás.
Intuición (memoización): es "anotar en una tabla" cada resultado ya calculado para no repetirlo. Fibonacci recursivo recalcula \(F(3)\) un montón de veces (por eso es \(\Theta(2^n)\)); con PD lo calculás una sola vez y lo reusás, y baja a \(O(n)\). PD = divide y conquista con memoria.

Principio de optimalidad: para que el resultado final sea el mejor, cada paso intermedio también tiene que ser el mejor. Si podés mejorar el todo usando partes que no eran óptimas, entonces PD no aplica.

Cómo se hace, paso a paso: (1) definir los casos base (los más chiquitos, que se saben directo); (2) escribir la recurrencia (cómo un caso se arma con los anteriores); (3) llenar la tabla de abajo hacia arriba (bottom-up); (4) si además querés saber cuáles elementos se eligieron, recorrés la tabla al revés.

Clásico 5.2 — Cambio de monedas (PD)
Descripción, características, entrada y complejidad.

Qué resuelve: dar un monto con la menor cantidad de monedas, usando un conjunto cualquiera de denominaciones. A diferencia del greedy (agarrar siempre la moneda más grande), la PD garantiza el óptimo con cualquier sistema de monedas.

Cómo funciona (en criollo): armás una tabla \(c[j]\) = mínimo de monedas para el monto \(j\), desde \(0\) hasta el total. Para cada monto probás todas las denominaciones: "si uso esta moneda, me queda el resto \(j - D_i\), que ya resolví antes" → te quedás con la opción que menos monedas use. Recurrencia: \(c[j]=\min_i\big(c[j-D_i]+1\big)\), con \(c[0]=0\).

Ejemplo: con \(\{1,3,4\}\) y monto 6, la PD da \(c[6]=2\) (\(3+3\)); el greedy daría \(4+1+1=3\). Este es justo el caso donde greedy falla y PD acierta.

Entrada: las denominaciones y el monto objetivo.

Complejidad: \(O(n\cdot v)\) (\(n\) denominaciones, \(v\) monto) — pseudo-polinomial: depende del valor del monto.

Clásico 5.3 — Mochila 0-1 (PD)
Descripción, características, entrada y complejidad.

Qué resuelve: llenar una mochila de capacidad \(W\) eligiendo objetos enteros (cada objeto entra completo o no entra) para maximizar el valor. Ojo: acá no se puede fraccionar — esa es la mochila fraccionaria (greedy) de UVA 3.

Cómo funciona (en criollo): vas objeto por objeto y capacidad por capacidad llenando una tabla \(V[i][j]\) = mejor valor usando los primeros \(i\) objetos con capacidad \(j\). En cada casilla decidís: ¿meto el objeto \(i\) o no?, y te quedás con la opción de mayor valor.

Recurrencia:

\[ V[i][j]=\begin{cases}\max\big(V[i-1][j],\; v_i+V[i-1][j-p_i]\big) & \text{si } p_i\le j\\ V[i-1][j] & \text{si no entra}\end{cases} \]

(\(V[i-1][j]\): no lo meto; \(v_i+V[i-1][j-p_i]\): lo meto y sumo su valor sobre la capacidad que quedaba.)

Entrada: los pesos \(p_i\) y valores \(v_i\) de los objetos, y la capacidad \(W\).

Complejidad: \(O(o\cdot W)\) (\(o\) objetos, \(W\) capacidad) — pseudo-polinomial: depende del valor de \(W\), no solo de la cantidad de objetos. También se puede por B&B (UVA 8).

Clásico 5.4 — Floyd-Warshall
Caminos mínimos entre todos los pares de nodos. Descripción, características, entrada y complejidad.

Qué resuelve: el camino más corto entre cada par de nodos de un grafo dirigido con pesos positivos, todo de una sola corrida. La diferencia con Dijkstra: Dijkstra te da las distancias desde un origen; Floyd te da la tabla completa de todos contra todos.

Cómo funciona (en criollo): arrancás con la matriz de costos directos (\(0\) en la diagonal, \(\infty\) donde no hay arista). Después probás, para cada par \((i,j)\), si hacer escala en un nodo intermedio \(k\) sale más barato que ir directo. Vas habilitando de a un nodo como posible escala (\(k=1\), luego \(2\), etc.) y la tabla se va mejorando sola. Es PD porque la mejor distancia usando los primeros \(k\) nodos como escala se arma con la que ya tenías usando los primeros \(k-1\).

Recurrencia:

\[ A^{k}[i,j]=\min\big(\,A^{k-1}[i,j],\; A^{k-1}[i,k]+A^{k-1}[k,j]\,\big) \]

Mini-ejemplo (3 nodos). Matriz inicial:

123
10411
2∞02
3∞∞0

Habilitando el nodo 2 como escala, la casilla \(1\!\to\!3\) mejora: \(\min(11,\; \underbrace{4}_{1\to2}+\underbrace{2}_{2\to3})=6\). Ir directo costaba 11; haciendo escala en 2 cuesta 6.

Entrada: la matriz de costos del grafo (\(n\times n\)).

Complejidad: \(\Theta(n^3)\) — tres ciclos anidados (la escala \(k\), la fila \(i\), la columna \(j\)).

UVA 6 ★ Backtracking

Descripción

Vas armando la solución paso a paso (una casilla, un elemento o un nodo por vez) y probás todos los caminos. Apenas ves que por un camino ya no vas a llegar a nada válido, volvés atrás (retrocedés = backtrack) y probás otro. Es prueba y error, pero organizado.

Características

  • Busca todas las soluciones posibles (búsqueda exhaustiva).
  • No es eficiente: exponencial en el caso general.
  • El espacio de búsqueda se modela como un árbol o un grafo acíclico dirigido.
  • La poda son las zonas del árbol que se evitan porque no pueden dar soluciones válidas.

Complejidad general

\(O(\#\text{hijos}^{\,\#\text{niveles}}) = O(b^d)\), exponencial en el peor caso. Las podas la hacen manejable en la práctica.

DFS — Recorrido en profundidad

Qué resuelve: recorrer todos los nodos de un grafo yendo lo más profundo posible desde el nodo actual antes de retroceder. La búsqueda comienza por un nodo, toma sus adyacentes y, a partir de uno de ellos, busca en profundidad; cuando termina con ese, sigue con el siguiente adyacente.

Características: es una aplicación directa de Backtracking. Hay que llevar la cuenta de los nodos visitados para no entrar en loops en grafos cíclicos.

Entrada: el grafo \(G\), el vértice de inicio \(V\) y el conjunto de visitados.

Complejidad: recurrencia de sustracción con \(a=n,\,b=1,\,k=1\) → \(O(n^n)\) teórico; en la práctica, por el control de visitados no se llama \(n\) veces por nodo y tiende a \(O(n^2)\).

Grafos dirigidos (clave conceptual): DFS solo sigue aristas salientes. Si arranco en un nodo sin camino dirigido hacia el resto, esos nodos no se visitan aunque estén en el grafo. Para recorrer todo hay que iterar sobre todos los nodos y lanzar un DFS nuevo desde cada uno no visitado → esto forma un bosque de DFS, no un único árbol.
DFS (profundidad): usa pila (o recursión). Va lo más hondo posible antes de retroceder. Es Backtracking.
BFS (amplitud): usa cola (FIFO). Visita por niveles/capas. Da el camino con menos aristas en grafos no ponderados.

Clásico 6.2 — Suma de subconjuntos
Descripción, características, entrada y complejidad · ejemplo con \(C=\{3,4,5,6\}\), \(v=9\).

Qué resuelve: dado un conjunto de números \(C\) y un valor \(v\), mostrar todos los subconjuntos de \(C\) cuya suma sea \(v\).

Características: se modela con un vector de 0s y 1s (o booleano) que indica, para cada elemento de \(C\), si se incorpora o no. Se poda apenas la suma parcial supera \(v\).

Entrada: el conjunto \(C\) de números y el valor objetivo \(v\).

Clásico 6.3 — N-Reinas
Descripción, características, entrada y complejidad.

Qué resuelve: dado un tablero \(N\times N\), ubicar \(N\) reinas de modo que no se ataquen. Una reina ataca a otra si comparten fila, columna o diagonal.

Características: ensayo-error por backtracking (se coloca una reina por fila; si ninguna columna es factible, se retrocede y se prueba otra). Representación eficiente: un vector de \(N\) posiciones con \(x[i]\) = columna de la reina de la fila \(i\), lo que evita dos reinas en la misma fila por construcción.

Chequeos de factibilidad al colocar la reina de la fila \(i\) en la columna \(j\) (la validez cuesta \(O(n)\)):

  • Fila: garantizada por la estructura (una reina por fila).
  • Columna: que \(j\) no aparezca ya en \(x[1..i\!-\!1]\) → \(c_i \neq c_j\).
  • Diagonal: para toda fila previa \(k\), \(|x[k]-j|\neq |k-i|\), es decir \(|f_i-f_j|\neq|c_i-c_j|\).

Entrada: el tamaño \(N\) del tablero (cantidad de reinas a ubicar).

Complejidad: recurrencia de sustracción con \(a=n,\,b=1,\,k=1\) → \(O(n^n)\) en el peor caso; mucho menor en la práctica por las podas de columna y diagonal.

Clásico 6.4 — Partición en mitades
Descripción, características, entrada y complejidad.

Qué resuelve: dado un conjunto de \(n\) enteros, encontrar (si existe) dos subconjuntos disjuntos cuya suma de elementos sea la misma en los dos; si hay más de una, mostrarlas todas.

Características: se recorre el conjunto y cada número se coloca en el subconjunto 1 o en el 2. Se lleva el acumulado de cada subconjunto para no recalcular la suma al final y poder podar apenas uno supera la mitad de la suma total. Poda inmediata: si la suma total es impar, no existe partición.

Entrada: el conjunto de \(n\) enteros.

Complejidad: recurrencia de sustracción con \(a=2,\,b=1,\,k=1\) → \(O(2^n)\) (dos opciones por cada uno de los \(n\) elementos).

UVA 7 ★ Juegos: MinMax y Poda α-β

Descripción

Un juego es una cadena de estados: arrancás en el estado inicial y cada jugada te lleva a un estado nuevo, hasta el estado final (game over). Todo esto se dibuja como un árbol: la raíz es el inicio, cada rama es una jugada, y las hojas son los finales, que valen un número (ej. \(+1\) gana Max, \(-1\) gana Min, \(0\) empate). La idea es mirar todas las jugadas posibles para elegir la mejor.

Características

  • Adversativo (los que nos interesan): los agentes persiguen objetivos mutuamente excluyentes — vs. colaborativo, donde persiguen un objetivo común.
  • 2 jugadores, Max y Min, con turnos alternados; información perfecta y sin azar (suma cero).
  • Cada jugada cambia el estado; los estados terminales tienen un valor numérico. Max maximiza, Min minimiza.

Nodos N y P (para juegos combinatorios)

  • Nodo P (previous): el que debe mover pierde con juego óptimo del rival.
  • Nodo N (next): el que debe mover tiene estrategia ganadora.
  • Regla: un nodo es P si todos sus sucesores son N; es N si al menos uno es P.

Algoritmo MinMax

Se calculan los valores de las hojas (los finales) y se van subiendo hacia la raíz: cuando le toca a Max, se queda con el mayor valor de sus hijos (quiere ganar); cuando le toca a Min, con el menor (quiere que Max pierda). El número que llega a la raíz te dice cuál es la mejor jugada.

Entrada: el estado del juego y de quién es el turno (Max o Min).

Complejidad: \(\Theta(k^n)\) (\(k\) = hijos por nodo, \(n\) = profundidad). El ta-te-ti completo es \(\Theta(9!)\).

Poda α-β

No es un algoritmo distinto: es una optimización de MinMax que evita explorar ramas irrelevantes, sin cambiar el resultado.

  • \(\alpha\) = mejor valor asegurado para Max en el camino actual. Nunca decrece.
  • \(\beta\) = mejor valor asegurado para Min en el camino actual. Nunca crece.
  • Se poda cuando \(\alpha \ge \beta\): el rival nunca dejaría llegar por esa rama.

Entrada: el estado, el turno y los valores \(\alpha\) y \(\beta\) (inicialmente \(-\infty\) y \(+\infty\)).

Beneficio: con orden de exploración óptimo, \(\alpha\text{-}\beta\) reduce la complejidad de \(\Theta(k^n)\) a \(\Theta\!\big(k^{\,n/2}\big)\) — equivale a explorar el doble de profundidad con el mismo costo.

Hay fósforos; cada jugador retira 1, 2 o 3. Pierde quien retira el último. Con 121 fósforos, ¿conviene jugar primero?

Primero, un ejemplo chiquito para agarrarle la mano. Tomemos 5 fósforos. Recordá: cada uno saca 1, 2 o 3, y pierde el que saca el último. Empieza A; veamos qué le conviene hacer a B en cada caso:

Cómo se lee: A arranca con 5. Saque lo que saque (1, 2 o 3), le deja a B con 4, 3 o 2 — y en los tres casos B puede completar hasta dejar exactamente 1 (verde). Con un solo fósforo, A no tiene opción: lo saca y pierde. O sea, desde 5 A no tiene escapatoria → 5 es posición perdedora para el que mueve (rojo).

La idea clave (el truco): a vos te conviene dejarle al rival 1 fósforo. ¿Y cómo te asegurás de llegar ahí? Después de cada jugada del rival, vos completás el grupo a 4 (si sacó 1, sacás 3; si sacó 2, sacás 2; si sacó 3, sacás 1). Así lo vas dejando siempre en 5, luego 1… Por eso las posiciones perdedoras son las que dejan resto 1 al dividir por 4: 1, 5, 9, 13, … es decir \(n \equiv 1 \pmod 4\).

Volviendo a 121: como \(121 = 4\times 30 + 1\), es \(121 \equiv 1 \pmod 4\) → posición perdedora para el que mueve. Por eso no conviene jugar primero: dejá que arranque el rival y vos completás a 4 cada vez.

Verificación analizando casos chicos (posición perdedora = pierde quien debe mover):

n=1 PERDEDORA (tomo el último y pierdo)
n=2,3,4 GANADORAS (puedo dejar al rival en n=1)
n=5 PERDEDORA (solo puedo dejar 4,3,2 → todas ganadoras para el rival)
n=9 PERDEDORA ...

Patrón: las posiciones perdedoras cumplen \(n \equiv 1 \pmod 4\): \(1,5,9,13,\dots\) Sea cual sea la jugada del rival (1,2,3), siempre puedo completar el grupo a 4 y devolverlo a "múltiplo de 4 + 1".

Como \(121 = 4\times 30 + 1\), es decir \(121 \equiv 1 \pmod 4\), la posición inicial es perdedora para quien mueve primero. → No conviene jugar primero.

Recalculá siempre el patrón con casos chicos antes de generalizar: confundir "múltiplo de 4" con "múltiplo de 4 + 1" invierte toda la conclusión.

Ejercicio 7.3 — Juego de las gemas (estilo Ejercicio 1 del simulacro)
Una pila de \(n\) gemas. En cada turno hay que dividir una pila en dos de tamaños distintos (\(n_1 \neq n_2\)). Termina cuando todas las pilas tienen 1 o 2. Pierde quien no puede jugar. Árbol parcial para \(n=7\).

Qué resuelve: determinar la estrategia ganadora. El estado no es un número sino el multiconjunto de pilas sobre la mesa. En cada turno se elige una pila \(\ge 3\) y se reemplaza por dos partes de tamaños distintos.

Ojo con las reglas: partir en dos partes iguales no vale (ej. \(4=2+2\) está prohibido; \(4\) solo se puede partir en \(1+3\)). Una pila de 1 o 2 ya no se puede dividir (el 2 sería \(1+1\), partes iguales). El juego termina cuando todas las pilas quedan en \(\{1,2\}\): el que tiene que jugar ahí no puede y pierde.

Cómo se construye el árbol (arriba): desde el estado inicial \(\{7\}\), por cada pila \(\ge 3\) se generan todas las divisiones en dos partes distintas (con \(n_1 \lt n_2\) para no repetir la misma jugada, ej. \((1,6)\) y \((6,1)\)); cada división produce un estado hijo, y se recursiona hasta que toda pila queda en \(\{1,2\}\) (hoja).

Entrada: el estado inicial (multiconjunto de pilas, \(\{n\}\) al comienzo).

Etiquetado N/P (así se decide quién gana): a cada estado le ponés una etiqueta.

  • P = pierde el que tiene que jugar (posición mala para vos).
  • N = gana el que tiene que jugar (posición buena).
  • Las hojas (todas las pilas en \(\{1,2\}\)) son P: el que llega ahí no puede jugar y pierde.
  • Regla hacia atrás: un estado es P si TODOS sus hijos son N (te lleve donde te lleve, el rival queda ganador); es N si AL MENOS UN hijo es P (podés dejar al rival en una posición perdedora).

Tu objetivo siempre es el mismo: dejar al rival en una posición P.

Ejemplo chiquito — ¿quién gana con \(n=5\)? Etiquetamos de abajo hacia arriba:

  • \(\{5\}\) tiene 2 jugadas: partir en \((1,4)\to\{1,4\}\), o en \((2,3)\to\{2,3\}\).
  • \(\{2,3\}\): única jugada, partir el 3 en \((1,2)\to\{1,2,2\}\), que es terminal (P). Tiene un hijo P → \(\{2,3\}\) es N.
  • \(\{1,4\}\): única jugada, \(4\to(1,3)\Rightarrow\{1,1,3\}\); de ahí \(3\to(1,2)\Rightarrow\{1,1,1,2\}\) terminal (P). Subiendo: \(\{1,1,3\}\) es N, y \(\{1,4\}\) (su único hijo es N) es P.
  • \(\{5\}\): sus hijos son \(\{1,4\}\) (P) y \(\{2,3\}\) (N). Como tiene un hijo P → \(\{5\}\) es N.

Conclusión: con \(n=5\) gana el primero, jugando \(5=(1,4)\) para dejar al rival en \(\{1,4\}\), que es perdedora. (Es la misma lógica que los fósforos: buscás la jugada que deja al otro en P.)

Clásico 7.4 — Ta-te-ti (tres en línea)
¿Cómo se modela con MinMax y por qué motiva la poda \(\alpha\text{-}\beta\)?

El juego: tablero \(3\times3\), dos jugadores (○ y ×) que ponen una ficha por turno; gana quien alinea 3 propias en fila, columna o diagonal.

Cómo se modela con MinMax: uno es Max (digamos ○, quiere llegar a \(+1\) = gana ○) y el otro Min (×, quiere \(-1\) = gana ×). Cada tablero terminal vale \(+1\) si ganó ○, \(-1\) si ganó ×, \(0\) si empató. Se prueban todas las jugadas y se suben los valores: en el turno de ○ se toma el máximo, en el de × el mínimo.

Por qué \(\Theta(9!)\): la primera ficha tiene 9 casilleros para elegir, la segunda 8, la tercera 7… En el peor caso (nadie gana hasta llenar) son \(9\times8\times7\times\cdots\times1 = 9! \approx 362.880\) hojas. Es manejable para una compu, pero muestra cómo explota el árbol (en ajedrez esto ya es imposible de recorrer entero).

Dato lindo: con juego perfecto de los dos, el ta-te-ti siempre termina en empate (la raíz vale \(0\)). Ninguno puede forzar la victoria si el otro no se equivoca.

Por qué motiva la poda \(\alpha\text{-}\beta\): como muchísimas ramas llevan al mismo resultado o a uno peor, α-β corta un montón sin cambiar la decisión. Por eso el ta-te-ti es el ejemplo clásico para introducir la poda.

UVA 8 ★ Ramificación y Poda (Branch & Bound)

Descripción

Es una optimización del backtracking para problemas de optimización (encontrar el óptimo, máx o mín). Su razón de ser: tener un criterio (la cota) que indique que, más allá de cierto punto, una rama no puede contener una solución mejor — así se descartan ramas enteras sin explorarlas.

Características

  • Sirve para optimización: principalmente minimización; los de maximización se adaptan (ver el truco de los negativos).
  • Ventaja: reduce mucho la cantidad de nodos del árbol que se visitan.
  • Se explora un árbol (o grafo acíclico dirigido) donde cada nodo es una solución parcial.

Estados de un nodo

  • Vivo: factible y prometedor, aún no generó todos sus hijos.
  • Muerto: no genera más hijos (ya se generaron todos, o es infactible, o fue podado).
  • En expansión: se están generando sus hijos ahora (solo uno a la vez).

Las tres cantidades clave (en criollo)

CantidadApodoQué es
\(lim\)el récordEl costo/valor de la mejor solución completa encontrada hasta ahora. Arranca con una solución cualquiera y va mejorando.
cota optimistael techoLo mejor que se podría lograr por esa rama: lo ya gastado + lo mínimo que falta (a veces "cortando con un cuchillo" el próximo objeto). Se usa para podar y para elegir la rama más prometedora (LC-BB).
valor garantizadoel pisoUn resultado realmente alcanzable por esa rama (ej., en la mochila, sin fraccionar). Sirve para actualizar el récord \(lim\).
Regla de oro (poda): si la estimación optimista (el techo) de una rama ya es peor que el récord \(lim\), se le clava la cruz roja y no se explora — es imposible que mejore lo que ya tenés. La cota debe ser efectiva y barata de calcular.
Ojo con las letras \(c\) y \(u\): la cátedra las usa con sentidos algo distintos según el problema. En la asignación, \(c\) es la cota optimista del nodo; en la mochila 0-1, \(u\) es el valor entero garantizado (piso) y \(c\) el fraccionario optimista (techo). Quedate con los conceptos —récord, techo, piso—, no con la letra.
Mochila 0-1 (recordatorio): mochila de capacidad \(m\); \(n\) objetos con peso \(p_i\) y valor \(v_i\); los objetos no se fraccionan; se busca maximizar el valor sin exceder \(m\). Truco: como B&B está pensado para minimizar, para maximizar se trabaja con los valores en negativo (minimizar \(-valor\) = maximizar valor, donde \(-38\) es "mejor" que \(-32\)). El techo se calcula fraccionando el próximo objeto para llenar justo el espacio libre.

Variantes

TipoEstructura de vivosCriterio
FIFO-BBColaExpande el más antiguo (por niveles)
LIFO-BBPilaExpande el último (en profundidad)
LC-BB (Least Cost)Cola de prioridadExpande el de menor cota (best-first) — el más usado

Cómo funciona (pasos conceptuales)

  1. Se mantiene una cola de nodos vivos y se saca siempre el más prometedor (menor cota, en LC-BB).
  2. Se expande ese nodo generando sus hijos y se calcula la cota local de cada uno.
  3. Se poda cada hijo por factibilidad y por cota (si ya no puede mejorar a \(lim\)).
  4. Si un hijo es solución completa mejor que \(lim\), se actualiza \(lim\); si no, entra a la cola de vivos.
  5. Termina cuando la cola queda vacía o ningún vivo puede mejorar la mejor solución.

Entrada: el estado inicial (solución parcial vacía) con su cota; la salida es la solución óptima.

B&B vs Backtracking: B&B expande siempre el nodo más prometedor de toda la cola de vivos (no el más profundo) y poda por cota aunque el nodo sea factible. Backtracking va en profundidad y poda solo por infactibilidad.

4 personas, 4 tareas; cada persona hace una tarea distinta; minimizar el costo total. ¿Cómo se calculan las cotas y se ramifica?

Modelado: asignar a cada persona una tarea distinta minimizando el costo total (una tarea por persona, sin repetir).

Récord inicial \(lim\): una asignación cualquiera da, por ejemplo, 73.

Cota de un nodo (el techo optimista): lo ya asignado + el mínimo de cada tarea que falta (aunque se repita persona). Ej. si \(a\to t_1\,(11)\): \(11+\min(t_2)+\min(t_3)+\min(t_4)\) sobre las personas libres \(=11+14+13+22=60\).

Se expande siempre la rama de menor cota (LC-BB). Al llegar a asignaciones completas mejores, el récord baja: \(73 \to 64 \to 61\). Todo nodo cuya cota ya iguale o supere el récord (65, 68, 78…) se poda de inmediato.

Óptimo \(=61\): \(a\to t_1,\ b\to t_3,\ c\to t_4,\ d\to t_2\) \((11+13+23+14=61)\).

Presupuesto \(K=10\). Proyectos (costo, impacto): \(P_1(4,10),\ P_2(5,10),\ P_3(6,9)\). Maximizar impacto sin superar \(K\). Ramificá y estimá complejidad.

Árbol binario incluir / no incluir (orden \(P_1,P_2,P_3\)):

En el árbol de arriba: incluir P1 y P2 da la solución de impacto 20 (verde); incluir P3 sobre eso es no factible porque excede el presupuesto (rojo); y la rama "no P1" se poda porque su cota \(17{,}5 \lt lim=20\).

Óptimo: \(\{P_1,P_2\}\), impacto \(=20\), costo \(9 \le 10\).

TSP y ciclos hamiltonianos (para conocer)
¿Cómo se acota el TSP y qué relación tiene con los ciclos hamiltonianos?

TSP (viajante): visitar cada ciudad una vez y volver al origen, mínimo costo. Es NP-difícil. Fuerza bruta \(\Theta(n!)\); PD (Held-Karp) \(\Theta(n^2 2^n)\). B&B acota reduciendo la matriz de costos: a cada fila se le resta su mínimo, luego a cada columna el suyo; la suma de lo restado es una cota inferior. La cota es no decreciente al bajar en el árbol → permite podar.

Ciclo hamiltoniano: recorrido cerrado que pasa una vez por cada vértice (NP-completo). Se reduce a TSP: se completa el grafo con aristas de peso 1 (existentes) y 2 (nuevas); si el TSP da costo \(|V|\), el ciclo existe en el grafo original.

Enunciado 2 — Jardinero
"Tablero de \(n\times n\). Una flor en cada fila, pero no dos en la misma fila, columna ni diagonal. (a) Dibuje el espacio de búsqueda parcial. (b) Pseudocódigo que indique todas las formas posibles. (c) Detalle las funciones hijos y poda."

Técnica: Backtracking — N-Reinas disfrazado (UVA 6). Señales: tablero \(n\times n\), una por fila, restricción fila/columna/diagonal, "todas las formas posibles", "funciones hijos y poda". Es N-Reinas con otra historia.

Cómo responder: representar con un vector de \(n\) posiciones (\(x[i]\) = columna de la flor en la fila \(i\)); árbol parcial probando columnas por fila; poda = chequear columna (\(c_i \neq c_j\)) y diagonal (\(|f_i-f_j| \neq |c_i-c_j|\)); complejidad \(O(n^n)\).

Enunciado 3 — Multiple choice de grafos
Objetivo de Dijkstra · qué comparten Dijkstra y Prim · Dijkstra vs Floyd.

Objetivo de Dijkstra: "calcular la ruta más corta desde un nodo origen a todos los demás" (no es MST, no detecta ciclos negativos).

Dijkstra y Prim en común: "ambos usan una estrategia greedy" (Dijkstra elige el nodo más cercano; Prim la arista más barata — no usan DFS ni generan árboles binarios).

Dijkstra vs Floyd: "Dijkstra encuentra caminos mínimos desde un origen; Floyd, entre todos los pares." (Dijkstra no funciona con negativos; no usan la misma estructura.)

Trampas frecuentes:
• Mochila: si dice "se puede fraccionar" → Greedy (UVA 3); si "objetos enteros / una sola vez" → PD (UVA 5) o B&B (UVA 8).
• Grafos: "desde un origen" → Dijkstra; "todos los pares" → Floyd; "conectar todo sin ciclos" → MST (Kruskal/Prim).
• Todas vs la mejor: "todas las soluciones" → Backtracking; "la mejor (óptima) con cota" → B&B.
• PD vs D&C: si los subproblemas se repiten (se solapan) → PD; si son independientes → Divide y Conquista.
